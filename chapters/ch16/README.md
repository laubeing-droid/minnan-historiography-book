## 从第16章关系表接到第17章网络指标

现在可以用同一批教学数据走完一条小路径：验证第16章关系表，选出有明确年份的通信事件，再调用第17章的图指标函数。不另装依赖，也不把第16章的全部关系都算成通信。

在仓库根目录运行（Python 3.10+）：

```sh
python chapters/ch16/code/relations_to_network.py --out chapters/ch16/results/my-bridge-run
python -m unittest discover -s chapters/ch16/code -p 'test_*.py' -v
```

输出目录必须是新的。程序写出 `events.csv` 和 `bridge_report.json`，后者保留入选与排除理由、原断言和出处、输入与代码摘要，以及网络指标。默认年份是1700—1710年，可用 `--start-year`、`--end-year` 指定另一个闭区间。

2026-11-12实跑结果：明确身份的人物名册为 P1、P2、P4；R5 对应一次 V2 寄信，C5 与 C11 是它的两条记录，不计成两次通信。保留两条出处及共同来源组，不据此声称有两份独立证据。无向存在图有3个节点、1条边，密度1/3，P4保留为孤立点。7项测试通过，包括重复来源、同一事件重复实例、待定判断、未知端点、空时间窗和反向年份。

这条路径只处理 `send_letter`，而且要求人物身份明确、关系判断接受、属于材料陈述、事件年份明确。共同参加活动、亲属关系、组织成员身份和分析假说都不转成通信边；未纳入项仍在排除表里。名册只是这一教学练习的观察边界，P4孤立不意味着现实中没有交往。

原第17章命令带有专为 A—H 练习写的敏感性情景，不能直接套在 P1、P2、P4 上。本桥接只复用其通用指标函数；不运行那些情景，不自动推断社群。它输出的事件表也不是一整套第17章输入包，不能单独传给原 `network_analysis.py --data`。

这次完成的是**合成教学数据的跨章运行**，不是正式史料研究。真实材料的身份认定、通信定义、名册边界、来源独立性和时间口径仍需研究者核定；本入口会拒绝未标为合成教学材料的来源。原附件、平行校订稿和历史记录均未改动。已运行输出见[桥接报告](results/bridge-2026-11-12/bridge_report.json)。
