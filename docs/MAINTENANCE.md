# 文档维护、版本与更正

维护时要让读者看清当前版本、可用内容和待查问题。本页说明修订与发布的做法。已有教学程序运行见[执行审计](CODE_EXECUTION_AUDIT.md)，正式数据复算和独立学术校对仍按另行安排开展。

## 一、改动放在正确位置

|改动|位置|同步关注|
|---|---|---|
|主线正文修订|作者授权后修改manuscript|章文件、合订副本、编写记录；不混平行版|
|文档入口或使用说明|docs及README|相对链接、术语、状态和公开边界|
|历史事实补充|当前项目史或缺件对照|保留历史快照，不覆写旧交付记录|
|教材代码提升|获准开展的chapters工作区|记录输入版本、运行及修补；与暂停中的正式史料复算分开|
|找回历史原件|先核来源和版本，再按授权收录|与新制件分开，不按数量猜身份|

修订从具体问题开始，先更新受影响的文件，再检查相关入口。已有文档能够容纳的内容，尽量放在原处，避免同一个规定在多份文件中逐渐出现不同说法。

## 二、合并前检查

先读取远端和本地状态，区分其他会话的未提交工作。只提交本次范围内的修改；同文件并发编辑逐处合并，不强推覆盖。新增内容检查隐私、来源、教学标记和失效链接，确认没有把历史指令重新当作当前授权。

文档检查与学术检查分别报告。链接通过只能说明入口存在；静态检查不能写成程序测试通过；一个章节完成修订不改变其他章的复核状态。

## 三、发布与里程碑

0.x表示写作期。达到全书完成标准并留下验收记录以后，才能发布1.0或称为终稿。一次文档修订可以正常提交，但应说明只完成了什么。全书23章156节、字数和10/75/15配比保持目标身份，未经复核不写成已达标。

发布说明应列：版本与日期、改动范围、材料来源、实际做过的检查、仍未运行或未复核的项目，以及读者需注意的不兼容变化。不要补造运行日志和历史下载记录。

## 四、外部链接与方法版本

外部文档可能更新或消失。重要引用保留题名、作者/机构、版本和用途；链接失效时寻找可靠替代入口，未取得全文时保留未核状态。新版本工具若改变参数或行为，先登记差异，不能因网页更新就批量改掉正文旧例。

## 五、长期可接续

优先使用普通文本、表格和清楚的目录，让离开某个模型或平台仍能阅读。保存的重点是材料与判断之间的联系，而不是所有聊天过程。工具、机器和协作者更替时，交接当前版本、待核问题、授权范围和下一步即可；不要让新人必须猜测旧会话才能继续。

下次维护从[文档总览](INDEX.md)、[缺件对照](MISSING_ITEMS.md)与[复核指南](REVIEW_GUIDE.md)进入。没有新材料或新结果时，保留当前状态即可；更新应让读者看见实际发生了什么变化。
