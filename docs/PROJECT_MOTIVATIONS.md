# 为什么建立书稿库和文献库

《一种闽南文史的未来：基于人工智能与现代研究方法》的[研究立场](POSITION.md)，说明了我为什么担心闽南文化及其历史知识的未来。这一页接着说明，我为什么把这些思考做成仓库，以及几个方向之间有什么关系。

## 从保存材料，到保留研究的可能

如果一种文化赖以存在的生活逐渐消失，后来的人要理解它，就会更加依靠留下的材料。问题是，留下来的东西未必完整，也未必容易读。许多材料分散在不同地方，使用不同语言，版本之间又有差异。网络上的介绍越来越多，反而可能使人误以为已经了解了对象，不再继续追问原来的依据。

我做这些项目，是想让材料和理解材料的方法能够一起留下。一个文件保存下来了，仍然需要知道它从哪里来，经过了什么整理，哪些地方读得清，哪些地方还不能确定。一个研究结论写出来了，也需要让后来者知道它回答什么问题、用了什么材料，以及还可能有怎样的解释。

这需要持续的工作。仓库的好处，是材料、文档、程序和修订记录可以互相联系，不必每次换一个人或换一个模型就从头开始。我希望把原来散落在个人经验和临时操作里的工作，逐渐变成别人能够接着做的东西。

## 书稿库解决怎样研究的问题

[minnan-historiography-book](https://github.com/laubeing-droid/minnan-historiography-book)承载《一种闽南文史的未来：基于人工智能与现代研究方法》。我希望它把研究从头到尾讲清楚：怎样从兴趣形成问题，怎样寻找和整理材料，怎样选择比较、统计、时间序列、空间和关系分析，最后怎样说明结果。

所以，这本书不能只讲为什么文化值得保护，也不能只介绍软件怎么用。前一种写法无法指导实际研究，后一种写法容易让读者以为图做出来了、程序跑完了，研究就完成了。我更希望读者知道每一步为什么要做，它解决什么困难，什么时候不适合做。

正文和附件应当互相支持。正文解释思路，附件让读者能看到数据怎样组织、方法怎样操作、结果怎样检查。程序运行成功可以帮助判断操作是否实现，但不能代替对史料和解释的判断。现有程序哪些已经运行、哪些仍有限制，以各项记录为准。

今后研究闽南或台湾历史的Agent也可以使用这本书。它可以据此寻找适合任务的章节，提出研究步骤和待核问题。但它必须回到实际材料，不能把书里的观点复制成没有限定的历史结论。

## 文献库让方法面对具体材料

[minnan-spanish-corpus](https://github.com/laubeing-droid/minnan-spanish-corpus)处理闽南—西班牙历史文献。它和书稿库的关系很直接：书里讨论研究方法，文献库则让这些方法面对实际困难。

一处字形读不清，一种音值没有足够依据，西班牙语释义与汉字的对应不确定，或者不同版本留下了不同记录，都不能靠多生成几遍答案解决。需要回到原件，分开各层材料，比较版本，保留疑难，再让能够判断的人继续处理。能否把这些工作组织好，正是研究工程是否有用的检验。

我不希望这个项目最后只剩下“用AI转出了多少字”。整理出来的材料应该能够支持后续研究：早期闽南语怎样记录，某些词汇和概念怎样翻译，语言材料怎样帮助理解当时的社会接触。这些问题要靠具体证据推进，不能因为语料规模增加就自动得到答案。

两库可以互相提供经验，却不能互相替对方宣布完成。文献库的当前状态以它自己的记录为准；书库写出一种方法，也不表示那种方法已经在全部文献上验证过。

## 其他方向怎样接在一起

我此前还考虑过多模态资料库、可复用的研究技能、历史时间线和协同研究框架。它们围绕的是同一件事：怎样使文史研究有比较稳定的材料和工作条件。这里说明的是方向，不把尚未核实的部分写成已经建好的具体仓库。

资料库先解决材料从哪里来的问题。文本、照片、录音、影像及其语境应当保存，检索和向量索引建立在它们之上。模型会更换，检索方式也会变化，原始材料不能随着某种技术被淘汰。

研究技能则帮助减少重复劳动。转写、校对、检查来源、核对人物地名等工作，可以逐步整理成可复用的方法。但省下来的精力应当用来提出问题和作出解释，而不是让研究者永远停留在检查机器错字这一层。

时间线和事件组织，是为了让分散记载能够比较。哪些事件值得进入主线，需要看它们与普通人的生活、生产条件和长期变化有什么联系。机器可以帮助筛选，但分数不能替人决定什么最重要。

协同框架让这些工作能够接续。不同的人和Agent做过什么、留下了什么疑问，后来者应当能够看见。这样，同一个问题可以不断增加材料和修正解释，而不是不断生成互不相干的新稿。

## 为什么不照搬法律工程

我在法律数学和软件工程中的经验，让我重视来源、过程与输出之间的关系，也让我更警惕工具把错误一步步传下去。但历史研究的材料条件和判断方式不同，不能把那一套控制全部搬来。

历史材料常常残缺，语境也不能完全转成字段。好的程序能够帮助我们组织和比较，不能因为自身结构严密，就保证对历史的解释唯一正确。文史项目需要保留足够的记录，让别人能检查和接续；也需要控制工程负担，让工具真正服务研究。

## 最后要留下什么

我并不认为建好几个仓库就能恢复原来的社会生活。它们能做的，是让后来的人更有条件了解曾经存在的文化，知道相关判断从哪里来，也能够提出不同意见。

保存这些条件，需要公开适合公开的材料和方法，也需要尊重隐私、权利和访问限制。不能公开的内容不能因为“为了研究”就全部放上网；无法找到的原件和没有验证的结果，也应当如实留下缺口。

对我来说，项目是否值得做，最终要看它有没有使研究变得更扎实：人是否更容易找到依据，能否比较不同解释，是否能从材料中提出新的问题，能否把别人的工作接过来继续做。如果只是增加了很多文件和流畅的AI文字，却没有改善这些条件，仓库本身也会变成一种表象。
