# 为什么建立这些仓库：研究动机与分工

本页说明《一种闽南文史的未来：基于人工智能与现代研究方法》及已明确关联项目为何存在。它陈述作者确认的动机与工作方向，不把计划中的基础设施写成已经建成的仓库。完整理论背景见[研究立场](POSITION.md)。

## 一、不是因为AI新奇，而是因为研究对象正在改变

作者担心，闽南文化的实践条件正在瓦解，而文化的展示、数据化和生成能力却越来越强。未来的人可能容易得到大量关于闽南的内容，却越来越难辨认其依据、理解它曾属于怎样的生产生活，或找到仍能解释这些关系的人。

因此，做仓库首先是为了保留可研究性：让原始材料、整理过程、分歧、方法和解释的依据能够接续，而不是仅留下一部难以修改的定稿或一套模型无法回查的回答。作者提出AI带来工具化、工程化与理性化机会，也可能参与知识被表象替代的最后阶段；这是项目的紧迫感，不是对技术的无条件乐观。

## 二、书库：把“怎样研究”公开出来

[minnan-historiography-book](https://github.com/laubeing-droid/minnan-historiography-book)承载《一种闽南文史的未来：基于人工智能与现代研究方法》。它要解决的不是“再写多少页闽南故事”，而是怎样建立从材料来源、问题识别、比较分析到人的解释判断的完整研究方式。

正文说明方法与研究问题，配套材料提供可以检查和学习的操作实例，文档说明来源、状态、局限与版本。公开代码和附件是为了让方法不止停留在散文中，但示例跑通只说明相应操作得到执行，不证明历史解释成立。

书库也为未来研究闽南或台湾历史的人和Agent提供方法入口。Agent可以据此选择章节、组织材料和生成待核方案，却不能把作者的理论主张直接输出为无争议史实，更不能把“参考本书”当成无需阅读原始资料的许可。

## 三、文献库：用具体困难检验工程方式

[minnan-spanish-corpus](https://github.com/laubeing-droid/minnan-spanish-corpus)面对分散、多语言、多版本的闽南—西班牙历史文献。它既提供具体材料的整理基础，也让研究工程接受实际困难的检验：字形如何判断、音读如何保留缺证、译义如何分层、版本如何互校、后来者怎样回到原件继续工作。

它不是凭模型生成完整文本就算完成的语料生产线。原文、机器处理、解释与疑难需要保持可辨认；来源及当前施工状态以该库自己的最新记录为准。书库不能替文献库宣布校对、独立复核或学术验收已经完成。

两库相互支持但不互相冒充：书库说明研究方法，文献库提供材料与方法试验场；文献库的一次技术成功不等于全书的方法均已验证，书库的理论框架也不能反过来决定一处古文献该读成什么。

## 四、更广的基础设施方向

作者此前提出的方向包括自动研究框架、可复用研究技能，以及闽南文史的向量或多模态数据库。这些是可确认的研究方向，不在本页未经核对地给它们编造仓库名、现成接口或完成状态。

- **多模态资料底座**解决“材料从哪里来”：文本、图像、音视频及其语境需要保存，向量只是帮助检索的表征，不能取代原始材料。
- **研究技能与工作流程**解决“重复工作怎样接续”：例如转写、校对、来源检查、人物地名核对。工具应让研究者把精力移向问题与解释，而不是把所有人变成机器输出的校字员。
- **历史时间线及事件组织**解决“分散记载怎样形成问题”：将事件放回时期、地域、生产与社会关系中。选录尺度服务研究，不把机器分数当成重要性的最终裁决。
- **协同研究框架**解决“不同人和Agent怎样积累而非重来”：保留可回查材料、研究步骤、分歧和未决问题，支持同题比较与交接，而不是以文件数量作为学术成果。

这些方向是否已经在某个仓库实现，需要另查那个项目的代码、数据、许可和状态。本页不承诺所有部分已经连通。

## 五、法律工程是经验来源，不是历史学的模板

作者的法律数学与软件工程工作带来了对约束、可核查过程和失真风险的敏感，但历史研究没有同样的封闭数学结构。历史材料的残缺、语境与竞争解释，不能为了让程序给出一个确定答案而被删除。

因此，相关法律项目可以作为工程经验的对照，不应被改写成这些文史仓库的理论基础或必要依赖。本书采用的是有助于研究的问题分工、来源保留和操作记录，不照搬法律工程的全部证明义务。法律仓库自身的目标与完成状态不由这份文史文档代为说明。

## 六、保存不是复古，公开不是交出判断

作者不是承诺利用AI复活已经消失的传统社会，也不把建设仓库解释为争夺一种文化的独占所有权。要保留的是人曾经怎样生活、理解和组织世界的经验，以及未来仍能理解、质疑和重新解释这些经验的条件。

公开让他人可以接续材料和方法，并不意味着应公开私人对话、个案、家庭信息或无权分发的材料。能够公开的依据和过程公开，不能公开的内容说明访问边界；缺件与未核状态如实保留。人的议题设定、价值判断和最终解释责任，不能因为工具越来越自动化而退场。

## 七、检验项目是否值得做

评价这些仓库，不只问新增了多少字、数据或程序，还要问：

1. 后来者是否更容易找到原始依据，而不是只能重复模型答案？
2. 不同材料和解释是否能够比较，疑难是否仍被看见？
3. 工具是否帮助形成更好的历史问题，而不是只加速生产通用叙述？
4. 个体研究是否能被接续，修正是否保留来路？
5. 面对与作者立场冲突的证据，项目是否仍能忠实记录并调整解释？

这些问题比“建立了一个AI项目”更接近本书和关联仓库的共同动机。
