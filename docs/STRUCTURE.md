# 仓库结构与章节工作区

本库把正在修订的书稿、需要保全的历史版本和用于运行程序的章节工作区分开存放。读者可以据此分清正在读哪一版文字、程序来自哪里，以及一次检查覆盖了什么。部分教学程序已有云端运行记录，全书真实数据复算和独立学术校对仍暂停。

## 一、写作主线与历史档案

| 目录 | 来源 | 内容 | 规则 |
| --- | --- | --- | --- |
| `manuscript/` | 《23章156节全文写作稿与配套附件》包（2026-10-30），剔除内嵌历史底稿 zip | 正文 23 章、附件 23 套（含代码示例）、全书目录、完成范围说明 | 作者授权下修订并登记；不改2026-10-30历史完成范围快照 |
| `round1_review/` | 《23章156节首轮校订与复算版》包（2026-10-30），同样剔除内嵌 zip | 平行正文（与写作稿 20/24 章不同）、校对复算记录（runs / reports / logs） | 原样保全；与 `manuscript/` 平行，**不混接** |
| `variants/` | 书稿资产 01_书稿Pages各版 | 55件实际历史版本文件（原稿、编校修订稿、单章草稿、全书级审读） | 原样保全；文件名后缀的 8 位哈希为源平台页面标识 |
| `plans/` | 书稿资产 02_空间历史文件 | 63件方案及候选稿，包括：三部曲总纲、工程方案 v1.0 与 v1.2 史学优先版、时间线施工总说明、事件筛选标准 | 原样保全；v1.0 已被作者批为过度工程，v1.2 为史学优先修订，二者都是历史文档 |
| `handover/` | 迁移包顶层与书稿资产清单 | 从这里开始、交付范围、交接任务书、缺件表、实交清单（json/csv） | 未改写；`书稿资产_` 前缀为原书稿资产目录内文件 |

书稿附件保留教学示例及其原有状态标记。把示例用于实际研究，需要另外检查输入、依赖和运行结果，这些工作放在 `chapters/`，具体记录见[代码运行审计](CODE_EXECUTION_AUDIT.md)。这样既能保留写作时的材料，也能继续完善程序。

## 二、活代码层：`chapters/`

```
chapters/
├── README.md      # 章索引表：章 ↔ 标题 ↔ 附件构成 ↔ 历史版本 ↔ 复算记录 ↔ 工作区状态
├── _shared/       # 跨章共用工具
└── ch01 … ch23/   # 每章工作区
    ├── README.md  # 本章档案位置映射 + 状态清单
    ├── code/      # 从附件提升或新写的可运行代码
    ├── data/      # 章数据（真实史料登记来源；教学虚构数据放 data/teaching/）
    └── results/   # 运行产物
```

**提升协议**（教材示例 → 可运行代码）：

1. 从 `manuscript/附件/chXX/` 复制到 `chapters/chXX/code/`，文件头注来源路径与提升日期；
2. 依赖登记 `code/requirements.txt`；
3. 教学虚构数据放 `data/teaching/`，真实史料放 `data/` 并登记来源权属——**教材示例与真实历史证据分开**；
4. 运行产物写 `results/`，与正文数字核对后在章 README 勾选；未运行一律 **NOT_RUN**；
5. 原附件中的 NOT_RUN / NOT_EXECUTED 标记在提升验证通过前**不得摘除**。

复算记录的历史分组（`runs/ch05_06_19_23`、`runs/ch07_11`、`runs/ch12_17`）是 2026-10 施工分组，章工作区与之一一对应的关系见各章 README。

## 四、不入库的内容

- 原始讨论对话（作者观点原话）——仅发布脱敏立场声明；
- Slack 施工线程导出——含个人信息；
- 源平台的内嵌底稿 zip、账号凭据类内容；
- `.gitignore` 兜底：`*.zip`、`*.pdf`、`slack*`、`__pycache__/`、`_scratch_*/`。
