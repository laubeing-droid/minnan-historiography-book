# 闽南地方志大事记对读与编年库：施工方案 v1.0

编制日期：2026-09-11  
任务：以用户已有闽南各县市地方志“大事记”为主，建立可以跨县并读、按时间筛选、对照不同记载、返回原页的区域编年库。  
本轮交付边界：方法与施工设计；已经核查下列研究论文、官方工具文档，尚未读取用户实际志书、统计书目页数或检查用户现有仓库。下述数据规模、软件性能和模型准确率均须试跑确定，不把方案示例当作史实或已完成的数据。

## 0. 总决策

先建设“史料编年库”，不直接让模型编写一部闽南通史。

推荐主线：

> 全量书目盘点 → 定位大事记并读取凡例 → 保留原条目抽取事件 → 时间、地点规范化 → 生成跨县同期表 → 发现同事件候选 → 对照、修订与合并 → 导出时间线、CSV、Markdown及Wiki页面。

原始志书文件是史料底本；SQLite是整理成果的主库；网页、CSV、Wiki和向量索引均为派生产物。无需先建设知识图谱数据库、多智能体系统或训练模型。

原始文件必须保留。PDF版的一部现代县志是这次工作的材料底本，但其中记载的古代事件不因此自动成为同时代一手史料。

已有历史研究框架只复用模型调用、文件目录与任务入口；本模块先能独立运行，再用稳定导出接入既有autoresearch、LLM Wiki。没有检查现有代码之前，不指定真实仓库文件的改动位置。

## 1. 先把四种“对齐”分开

| 工作 | 实际含义 | 禁止替代它的操作 |
|---|---|---|
| 时间对齐 | 将公元、民国、年号、农历、干支、相对时间放到可比较的时间范围中 | 缺月日自动补成1月1日；只按字符串排序 |
| 空间对齐 | 辨明事件所指历史地点及其有效年代，并提供今地检索入口 | 把现代县区名称倒灌古代；把县志所属县当作所有事件发生地 |
| 同事件对齐 | 把不同书对同一个事件的记载联系起来，同时保留异文 | 看到同年、同灾种或相似句子便删除重复项 |
| 过程对齐 | 联系同一过程内不同节点及不同县的地方表现 | 把所有地方行动合成一个事件；把先后顺序写成因果关系 |

时间轴本身是一种呈现方式，不是事件同一性判断。第一批材料只完成时间排序，也应当立即能看，不能等全部考证完毕。

## 2. 研究范围与第一轮材料

以现有书目为准，先用漳州、泉州、厦门作为浏览分组，不据此宣称历史文化边界始终等同于今天的行政区划。对跨界地方或域外关联事件使用“核心范围／关联范围／待定”的范围标签，不先进行不可逆排除。

第一轮处理全量书目的“大事记”，同时读取该书的凡例、目录及理解日期所需的编纂说明。建置沿革部分按地名消歧需要补读，不要求先对全书进行完整结构化。

原文条目全收，不先按某种历史解释筛选“重要事件”。农业、土地、人口、水利、财政、社会组织、教育、产业、交通及国家治理等，均可作为研究标签；标签不替代原文，不把“文史”预先缩成民俗、建筑与旅游名录。

V1成果的名称应明确为“基于已收录地方志大事记的闽南编年库”。大事记之外的历史过程，后续按研究问题补入专志、人物、档案及论文，不宣传为已经穷尽全部历史。

## 3. 网上研究与工具选型

### 3.1 直接可借鉴的研究

Chen等人的《Treating a genre as a database》提出将成批地方志视为可共同查询的文献集合，并在整体分布与逐条细读间往返；这比逐本摘要后再拼接更适合本任务。[S1]

Schäfer等研究元代灾害记载时，区分事件、记录实践与后世编纂，讨论了上报日期和发生日期的差别、不同文本之间的抄录，以及把连续过程过度拆分所产生的问题。因此本项目同时保存原条目、事件节点和过程关系，不单纯统计关键词出现次数。[S2]

CHisIEC提供古代汉语实体与关系抽取的研究资源。它可以作为任务设计和外部测试参考，但不证明任何模型在用户这批闽南县志上的实际准确率，更不能替代本地样本校核。[S3]

### 3.2 建议采用的工具组合

| 环节 | 选择 | 用法与边界 |
|---|---|---|
| PDF抽取 | PyMuPDF | 先取现有文字层与文本块，检查阅读顺序；没有可用文字层才走图像识读。文档明确指出原始文本顺序未必等于阅读顺序。[S4] |
| 复杂版面补充 | 已有视觉模型；必要时对MinerU做小样本比选 | MinerU官方仓库提供文档转Markdown/JSON能力；这不等于已验证其古籍竖排识别效果，不为本任务强制安装多个重型解析器。[S5] |
| 纪日换算 | 中研院“两千年中西历转换”作为校验与批转工具；将实际换算结果缓存 | 官方网页支持年号、闰月、干支及批量文件输入，但未据此确认存在可直接调用的稳定开放API。[S6] |
| 历史地名 | CHGIS下载数据／查询结果＋用户志书沿革材料 | 利用带有效年代的地点记录；现代沿革及乡村微地名以本地补充为主，不将县治坐标等同历史县界。[S7] |
| 主库 | SQLite | 保存书目、原条目、事件与关系；关键词、时间、地域筛选优先，暂不以向量库为主库。属于本方案选型。 |
| 浏览 | 本地网页＋vis-timeline | 其官方组件支持时间点、区间、分组与缩放；本项目另写日期精度与存疑样式，不假定组件自行理解历史不确定性。[S8] |
| 展示导出 | UTF-8 CSV、Markdown、Wiki派生页面 | 数据库统一导出，禁止维护互不一致的多套主表。属于本方案设计。 |

LoGaRT是方法与功能参照，不作为接收用户全部文件的必需云平台。第一版不做复杂地图动画、不接图数据库、不引入多人权限体系。

## 4. 最小数据结构：原条目与整理事件分开

用六张小表即可表达核心关系。嵌套字段可以用SQLite中的JSON文本保存，第一版不必为每个属性拆表。

### 4.1 `sources`：书目和版本

记录：稳定的`source_id`、书名、卷册、版本／出版年、编纂者、原文件路径、声明记述范围、采集来源、凡例日期规则、大事记页段、页面处理状态、与其他版本的关系。

重要区别：出版时间不等于记述下限，文件名不替代版权页和凡例。新旧版、影印版、续志分别登记；同文件重复导入不新增一套书目。

### 4.2 `records`：原始大事记条目

记录：`record_id`、`source_id`、PDF实际页序、书内印刷页码、条目序号、原文、原日期表达、继承日期的上下文位置、识读状态。

保留整条原文，不以模型摘要覆盖它。原条目跨页时保存起止页，书内页码不清时可留空，但实际文件页序必须可回看。页段有重叠输入时，同一原条目只登记一次。

底本、抽取文本和校订文本有区别：抽取文本可能有识读错误；修正另外保存，不静默改写底本。段落坐标能顺手保留就保留，不作为每条入库的额外负担。

### 4.3 `events`：整理后的事件节点

记录：`event_id`、中性标题、摘要、当前采用的时间与地点解释、类型、核读状态、异文状态。发生日期有争议时可以没有唯一采用值，保留候选组。

一个事件允许涉及多地；一个事件的时间精度可以只有年。标题可以编辑，不影响稳定编号。

### 4.4 `evidence`：原条目与事件的对应

连接`record_id`与`event_id`，保留该原条目支持此事件的原文片段、该来源自己的日期／地点／主体／数字，以及关联理由与核读状态。

它解决两种常见情况：一条大事记包含多个可区别的行动；一个事件在多个县志或不同版本中出现。事件合并只调整对应关系，不删除原条目。

原条目中的数字、事件阶段与日期口径不一致时，保留在各自证据行中。例如两志关于受灾户数的不同数字不能被模型合成一个新数字。

### 4.5 `places`：轻量历史地名表

记录：`place_id`、原名／异名、地点类型、有效起止年代、历史隶属关系、今地对应、今地对应有效时点、依据、确定程度。

一个旧地名可以对应多个今地；同名异地保留不同候选。历史地点对应不明时，不造坐标、不强选第一条搜索结果。

### 4.6 `relations`：事件间关系

第一版只需：`part_of`（属于一个过程）、`precedes`（有根据的先后）、`related`（有关联）、`reported_causal`（材料明确叙述的因果）。研究者自己的因果假说单独标为`hypothesis`，不能显示成已考定事实。

仅由同年、同地或语义相似得到的候选，不生成因果边。若只有同一年而无明确先后，不能建立`precedes`。

人工修订、合并、拆分可以另记一份`decisions.jsonl`。重跑时在机器结果上应用人工决定，不覆盖已核修改；旧事件编号保留跳转，避免Wiki引用失效。

## 5. 时间规范化：保存精度，不制造精确性

### 5.1 每一条日期应保留的信息

`date_raw`：原日期表达；`date_context`：继承的朝代、年号、年、月及其来源；`calendar`：历法口径；`date_role`：发生／上报／批准／实施／事后追记等；`precision`：日／月／年／季／时期／未知；`temporal_kind`：单次发生／持续过程／发生时间不明区间；`normalized_candidates`：换算候选；`conversion_note`：换算工具、结果及必要说明。

这些是内部字段。用户界面默认只显示“原纪年、对齐时间、精度／存疑提示”，不展示JSON。

### 5.2 继承日期的正确方式

把章、年、月标题视为上下文，而不是只给每页孤立识别。支持“同日”“是月”“是年”“翌年”等表达。

继承只在同一本书、同一条时间线的有效上下文内发生。跨页可继承，但跨书、进入新章节、出现回叙或另一套纪年时必须重新判定。上一条正文提及的某一年，不自动成为下一条的年标题。

### 5.3 年号、民国纪年与农历

识别朝代、政权、帝号、年号和年数，尤其处理同名年号、改元年、闰月与干支。民国年数可以辅助换算年份，但不能仅凭“民国”二字断言月日已采用公历；依据本书凡例和具体记载。

年号与公元年的对照标签，不等于该年号年严格从公历1月1日持续到12月31日。只有年级信息时可用对照年份做浏览分组，但不能据此宣称精确公历区间。需要月日级比较时，再处理历法边界。

中研院工具官方页面给出服务范围为西元元年2月11日至2101年1月29日，并提供至多1000行的单次批量转换。大批量任务分批处理，不截断全部数据。官方说明同时明确：省略日数返回月首日，省略月日返回年首日。[S6]

**因此返回的首日只可用作范围计算的一个边界，绝不作为事件发生日。** 不支持的年代、不明年号、换算失败的条目继续保留原纪年，可出年代分组或待定区，不阻断总表。

施工不得猜造该网站API。先验证可用批转方式；结果可导入本地历日缓存。V1以已有公元标注和可靠年号表先完成年级对齐，精确日换算按需补充。

### 5.4 持续范围与不确定范围

以下仅为说明性构造示例，非闽南史实：

| 原文 | 结构解释 | 显示 |
|---|---|---|
| “1931年，设某机构” | 单次事件；仅知年份 | “1931年，月日未详” |
| “1931年至1933年，修筑某路” | 真实持续过程 | 持续条 |
| “约在1931至1933年间设某机构” | 单次事件发生日期不明 | “约1931—1933年间”，用不同样式表达不确定范围 |
| “是年秋，洪水” | 依上级年标题、原历法解释季节 | 保留“秋”，不默认等于公历9—11月 |

内部排序边界可以用完整日期表示，但这些是计算用边界，导出和界面不得将其解释成精确发生时间。

若A最晚可能发生的时间仍早于B最早可能发生的时间，才能由日期推出A先于B。时间范围重叠时，可并列展示；数据库为稳定显示而选的顺序不是历史上的先后结论。

### 5.5 西历与前公元支持

中研院页面说明了儒略历、格里高利历及换历设置，因此不可直接假定任何第三方工具返回的“西历”都与前端日期库的默认口径一致。[S6]

内部统一日级比较采用明确声明的推算公历口径；来自历史儒略历的结果需先转换，原结果及历法仍保留。不得根据浏览器所在时区改变历史日期。没有时刻的古代纪日不是UTC时间戳。

如语料含前公元年份，显示采用历史纪年且不出现“公元0年”；内部可用天文年号，但必须隔离显示转换。前端日期解析器需测试1—99年、前公元和历法边界，不准用现代JavaScript日期构造默认行为猜测古代日期。

## 6. 地点规范化：不是现代行政区划替换

分开保存三个维度：记载来自哪部县志；事件当时发生或涉及何地；用户希望按哪个今地区域筛选。

一部县志可能记载省级政策、邻县灾害、域外战争或本地人的外地活动，不能全部贴到本县地图上。将“发生地、受影响地、主体籍贯、政策适用范围”按需要分开，确实不明就不填写。

CHGIS的设计将名称、边界、治所或隶属变化与有效时段联系起来；但其大量县级及以下对象是点位而非完整辖区面，不能把数据当作任意年代的精确县界。[S7]

V1只做地名、隶属和检索分组，地图不是前置条件。今地筛选可允许一个事件出现在多县轨道中，但这些是同一个事件的多个显示实例，不能因此重复统计。

## 7. 事件抽取与跨县对齐

### 7.1 抽取粒度

提取能够独立陈述的行动、变化或发生事项，同时保留完整原条目及其叙事结构。不把每个动词拆成独立事件，也不把包含多个时点的段落压成一个日期。

例如一条原文明确写到六月受灾、七月赈济、翌年迁居，可以建立三个事件节点并保留共同原条目。它们可属于一个过程，但仅有前后顺序不足以证明灾害导致迁居。

“本年统计全县人口若干”应标注为统计／状态观察，不默认等同于一次历史行动。“未发生某事”保留否定，不反向生成肯定事件。

### 7.2 先召回候选，再判断关系

主召回按时间范围、历史地点及其隶属、具体人物／机构／工程名称、动作和对象组合筛选，不做全库两两模型比较。

另开一条“特征名称强匹配”通道：即使日期不同，也召回高度独特的同名机构、工程或人物行动，以发现错年、异文及OCR误识。时间约束不能把真正的日期冲突预先排除。

无明确时间的记录进入未定年队列；可用具体对象寻找候选，不为了匹配强补日期。向量检索仅在样本显示词面方法漏召回后增加，定位仍是候选发现而非证实。

### 7.3 输出三种结果，不只有合并／删除

| 判断 | 操作 |
|---|---|
| 同一事件的多处记载 | 链接到同一`event_id`，保留各条原文、日期和数字 |
| 同一过程中的不同事件，或同一大事件的各地表现 | 保持独立节点，用`part_of`／`related`关联 |
| 同期而不同的事件，或证据不足 | 保持独立；证据不足者可列候选，不自动合并 |

模型必须给出依据到具体片段，例如“机构名称、设立动作与日期一致”；不能只输出“相似度0.93，所以合并”。

禁止把相似度当作“历史真实性概率”。模型抽取把握、关系判断把握与史料可信程度是不同问题。

### 7.4 典型误合并防护

下面均为构造示例，不是史实：

- 甲县五月洪水，乙县同年七月洪水：不能仅因同年水灾就算同一场洪水。
- 甲志记某堤开工，乙志记该堤竣工：同一工程的不同阶段，不是重复。
- 省级命令发布与各县落实：不同动作；视材料联系为同一政策过程。
- 甲志记某机构在Y年成立，乙志记同一机构在Y+1年成立：可以提出同事件日期异文，不以更晚出版或记载数量多自动裁定。

聚类不得使用“只要存在一条相似边就全部串起来”的规则。A与B相似、B与C相似，不足以自动把A、B、C认定为同事件；加入事件组时重新检查组内具体对象与冲突。

### 7.5 文字重复与独立证据

相同扫描副本可以文件去重；不同书的同文抄录必须保留书目来源。

材料明示引自前志、旧志、上级志书时记录来源关系。只有措辞相似时标“疑似承袭”，不伪造传承谱系。三本志书的三条记录不自动等于三条独立证明。[S2]

## 8. 人机分工与核读界面

默认用一个主模型完成抽取、摘要和候选判断，程序负责页码映射、日期规则校验、候选筛选、写库与导出。只把难页、相对日期、同事件冲突等任务送入更强模型或人工；不常驻多模型同屏互审。

不用逐条人工批准全部材料。原始条目可直接进入“据原志整理、未经逐条核读”的视图；清楚的字段自动写入，配合分层抽样。含糊的归并保留为候选，也不妨碍其在同期表出现。

人工重点处理：日期换算与原文冲突；同名异地；事件同一性争议；同事件异文；需要采用哪一种解释的关键节点。自动归并最初只处理完全明确的重复；扩大范围以前，先在本地校核集验证。

核读页左右并排显示两条或多条原文，附书名、版本、PDF页与印刷页。按钮只需“同一事件、有关联不合并、不同事件、暂不决定、修订字段、撤销合并”。人看正常中文，不看模型JSON。

用户对一组同类问题可以批量处理。一个疑难条目的未决状态只影响这一条的采用解释，不冻结整本书或整个项目。

## 9. 用户最终使用的界面

### 9.1 跨县同期表：第一交付

行按年或用户选定粒度排列，列按县／来源书排列。每格展示当期条目数和可展开条目，点击返回原页。允许按历史地点、今地或来源书切换分组，三种口径明确标注。

空白不能统一显示成“无事”。区别：材料未收录；页面缺失；尚未处理；该时段已检索但没有检出条目。即使最后一种，也不推断当时没有事件。

### 9.2 可缩放多轨时间线

横轴为时间、纵轴为县市或历史地理分组，支持主题筛选、书目筛选、已核／未核、显示原条目／整理事件。模糊日期和持续事件使用不同图例。

拉远展示年份／时段计数，放大才加载条目，避免把全库所有事件卡片一次渲染。省略加载是显示策略，不是数据量上限。关闭拖动修改事件日期；日期修改应通过核读操作。

### 9.3 事件异文对照卡

显示标题、采用时间或候选时间、涉及地点、全部来源原文及字段差异。某事件“两个日期有异文”与“两条记录是否同事件尚未确定”分别显示。

### 9.4 专题与过程视图

农业水利、人口迁移、土地与财政、行政与社会组织、交通产业、教育制度等专题按需选择。关联线有关系类型及依据；研究假说单独显示，不与原志明确叙述混同。

该视图可在主库完成后再逐步增强，不是第一版出总表的前置条件。

### 9.5 材料覆盖视图

按“书目×记述时期×处理状态”展示：现有多少版本、声明覆盖哪些年份、哪些页已处理、何处缺页或待核。

事件条数、记载条数、收录书目数、来源独立性是不同统计口径。可报告“某时期在已收录大事记中记载较密”，不可由此自动断言该时期社会变化更剧烈。LoGaRT研究特别强调理解集合自身的时空分布，避免被数据偏倚误导。[S1]

## 10. 施工顺序与每步交付

### A. 全量盘点，先把输入摸清

扫描用户指定目录，登记文件、版本、文字层情况与可见目录。定位大事记页段、读取凡例的纪年说明。抽看开头、中间、末尾以及双栏／竖排页面，检查文字顺序及页码映射。

交付：书目清单、大事记页段清单、日期规则说明、缺文件／缺页／版面问题清单。任何总页数、条目数或OCR比例都来自实际盘点，不预填。

### B. 用真实小样本打通全过程

按已有材料选择约3—6部有重叠年代且版式有差异的志书；若具备条件，再包含同地不同版本。规模不是强行配额，没有某类材料就不虚构。

抽取约200条作本地校核样本，覆盖普通条目、跨页条目、年月继承、年号、地点沿革、同事件多记、同主题不同事件和日期冲突。对真实样本不足的边界问题另设明确标识的构造测试，不混入历史数据库。

交付：可核读样本、样本编年表、候选对照集、第一版浏览页，以及错误类型与模型调用记录。

### C. 全量入库与时间、地名对齐

按同一流水线处理全部指定书目。按书／页段保存进度，失败条目进入问题清单，其余继续；重跑复用已处理成果。人工修订优先于重新生成的机器建议。

交付：原条目库、规范化事件及证据、历史地名表、全域同期表、可见的未定年／地点待定清单。

### D. 跨书对照、界面与导出

执行候选召回、关系判断、同事件归并与异文展示；完成多轨时间线和核读操作。输出CSV、Markdown、Wiki派生页及统计说明。

全域检索和筛选必须真实访问入库数据，不能用静态样例伪装已接通。大规模视图采用分段加载，原件链接必须可用。

## 11. 验收：衡量整理是否可靠，而非界面是否漂亮

以下是建议验收要求，不是已有模型性能结论。

| 项目 | 验收方法 |
|---|---|
| 出处可返回 | 每个正式入库事件至少链接到一条原文，且该原文有有效源文件与实际页序；自动检查关联完整性并人工抽看定位 |
| 条目未漏抽 | 对抽定连续页段人工列出应有条目，再比对抽取结果；不能只检查已抽到的条目 |
| 日期处理 | 对可判定样本核对年份、月日、纪年继承与历法；不明日期正确保留不明，不计作误填 |
| 不制造精度 | 所有缺月日、季节、约年、换历边界构造测试不得显示伪造的精确发生日 |
| 地点不误归 | 核对来源县与事件发生地、历史隶属与今地，包含同名异地测试 |
| 同事件判断 | 在含正例、近似反例与不确定例的对照集上分别报告误合并、漏关联与待定；不把待定当作正确合并 |
| 版本与异文保留 | 同事件不同日期／数字可以并列；原条目不因合并丢失 |
| 重跑可用 | 同批文件重复处理不重复增加记录；人工修订不被覆盖；拆分归并可撤销 |
| 覆盖说明准确 | 缺材料、未处理、已处理未检出分开；显示统计注明计数单位 |

可将约200条真实样本中的条目抽取召回、可判定日期／地点规范化正确率暂设为不低于95%的首轮改进目标；分项报告，不混成一个“总准确率”。日期伪精确、原文丢失、明显误合并作为必须修复的缺陷。

“样本未发现误合并”不等于总体误合并率为零，尤其不能拿很小样本宣传99.9%可靠性。若跨书归并尚未达到可接受水平，保留候选形式，仍交付完整同期表；不以低质量合并伪装完成。

## 12. 成本和运行规模

只抽大事记及必要上下文，不重复处理全书。优先文字层，图像识读仅处理没有可靠文字的页。按年代标题切成不破坏上下文的块；邻块重叠须去重。

模型只承担程序难以完成的语言任务，不承担分页编号、SQL筛选和所有日期算术。明显已解决的条目不重送模型，候选比较只送相关片段。

试跑记录输入输出token、页数、条目数、失败重试与人工核读量。全量工作量依据实际盘点和样本估算，不在书目未读前承诺金额、条目数或耗时。

数据保存在本地。原件、数据库和人工决定做普通文件备份即可，不为个人研究另建复杂审批、密钥或审计平台。

## 14. 与既有研究体系的接口

Wiki页面按事件ID导出，包含时间、涉及地点、摘要、原文与书目页码、异文及关联。未经核读的解释明确标注。Wiki是阅读层，不反向自动改写数据库底本。

向量索引可选择索引事件摘要和原文片段，但必须带`event_id`、`record_id`、`source_id`与页码。向量库删掉后应能从主库重建，不承担唯一保存职责。

autoresearch取得某时段／地区／主题的记录后，可以提出补读问题或外部检索任务。外部材料作为新来源登记，不能偷偷替换本地志书原文，也不能将模型根据自身知识补写的内容作为另一条史料。

外部补充优先用于解决已发现的缺口与异文。福建党史方志网提供厦门、漳州、泉州等地方入口，可作为书目、补遗与地方资料的检索入口；各网页具体记载仍需回到可辨识的出处。[S9]

## 15. 可直接交给执行Agent的启动任务

你要在用户已有历史资料目录上实现“闽南地方志大事记对读与编年库”，依据本方案施工。先检查现有仓库／目录，复用已有模型入口，不臆测项目状态，不修改无关工程。

第一动作是自动盘点文件、版本、文字层及大事记页段，读取凡例日期口径，不先全库向量化。随后选真实小样本打通“原页—原条目—事件—跨县同期表—对照页”的全过程，再按同一流程全量处理。

原件只读；书名、版本、页码、原文不可丢；原始条目与整理事件分开。模型摘要、归并建议和人工解释不得伪装为原文。缺失字段留空或待定，不得凭模型知识补造事件。

日期保存原纪年、继承上下文、历法、精度及时间角色。缺月日不补精确发生日；上报日和实施日不替代事件发生日；持续过程与发生时间不明的范围分开。

地点分开记录来源县、当时发生地及今地筛选入口。跨县对齐输出“同事件、同过程但不同事件、不同／待定”而非只会去重。允许一个事件有多个不同日期解释及多个地点。

采用Python、SQLite、一个主模型和本地网页。复杂扫描页按需调用既有视觉模型或经试跑验证的解析器。不要先建设大型图谱、多Agent编排或全库人工审批。

优先交付可浏览的完整同期表、可回看的原页和原文、候选异文对照，再增强时间线与专题关系。疑难条目留在可见待定区，不冻结其他任务，不以隐藏问题或吞掉材料伪装成功。

交付必须包含真实运行的代码、可配置入口、主库、CSV／Markdown导出、核读界面、真实样本验收及运行说明。只依据实际执行报告已完成项；未验证的API、准确率或旧书识别能力如实标明，不用假数据替代。
