# 01｜选材标准与边界

## 一、筛的不是“原始资料是否值得存在”，而是“进入哪一种研究产物”

地方志编纂者把一件事放进“大事记”，不等于研究者必须把它放进闽南历史主线。应区别四件事：原书是否记载、记载了什么、记载有多可靠、对当前研究有什么意义。

本包不以“水”作为删除标签。它的操作含义是：**没有可辨识的实际后果，也没有能够说明的研究用途时，不占据主线；原文仍在底库。** 本标准可用于各时代、各类资料，不预设某一时代、国家或编纂群体的所有记载一概无价值。

双通道：一条以历史后果为中心，一条以研究解释力为中心。Historical Thinking Project对“长期、大范围改变”与“小人物经历揭示更大历史问题”的区分，提供了基本方法启发；以下12条是为本项目设计的操作规则，不是史学界已经验证的统一量表。[1]

## 二、进入主线的七项历史后果标准

满足其中一项即可提出候选，**不是必须同时满足七项**。但需要讲明具体对象、实际改变、影响范围及时间性质。范围与持续性是判断维度，不是用数字加总的“重要性分”。

| 编码 | 标准 | 要问清楚什么 | 不能冒充依据的东西 |
|---|---|---|---|
| C1 | 生产、生计与资源分配发生实质改变 | 土地、佃租、税负、劳作、生产组织、资源取得或分配，谁失去什么、谁获得什么？ | 投资计划、产值口号、经济发展形容词 |
| C2 | 权力、制度与组织关系实际重组 | 谁获得/丧失征收、管理、分配、执行或组织权？规定是否实施，旧安排是否被替代？ | 发文件、开会、挂牌、普通任免本身 |
| C3 | 人口、迁移、聚落及群体处境改变 | 人群为何迁出/迁入，聚落是否重组，生活机会、身份或负担怎样改变？ | 人口数字单点、人口众多、名人到访 |
| C4 | 区域联系和交换条件改变 | 运输、贸易、渡运、市场或其他网络实际怎样连接、断开、转向？有无使用和后果？ | 开工典礼、建成宣传、地图上两点距离 |
| C5 | 农业生态、水利和环境条件改变 | 灌溉、耕作、生境、土地可用性或风险结构怎样变化？是否持续？ | 出现“水灾”“生态”“水利”三个字即判重大 |
| C6 | 生存危机、强制和不可逆损害 | 饥荒、战争、瘟疫、迁逐、暴力等对生命、生计、群体延续产生什么具体后果？ | 新闻关注度、正面或负面立场、无出处的损失推断 |
| C7 | 知识、技能与共同实践的再生产改变 | 谁还能学习、传授、参与和维持一种实践？组织、人员、场所与条件如何维持、改造或中断？ | 文化节、评奖、挂牌保护、被媒体命名为“传统” |

### 主线判定的强度要求

“实际改变”至少应是来源明确报告的改变，不是模型把计划改写成现实。进入主线通常还应有县域及以上关联、跨地域影响、长期后果、严重不可逆损害之一，且材料足以支撑这个层次。少数大范围即时灾难并不需要“持续多年”才重要。

程序以`major/specific/potential`区分有材料支撑的重大后果、局部具体改变、尚待证实的潜在影响。`reported_fact`只表示“所据材料作此报告”，不表示该记载已由独立史料证实。

资料只说明局部改变时，可以进专题，不必为了保住价值而夸大成全闽南大事。非常重要却证据薄弱的事项仍可进待核线索；不以“缺证”冒充“不重要”。

## 三、进入专题的五项研究价值标准

这五项解决“规模不大、后果不显著，但值得研究”的材料。**必须回答具体问题，不能只说‘有研究价值’。** 程序要求绑定配置中已启用的问题ID。

| 编码 | 标准 | 合格理由 | 不合格理由 |
|---|---|---|---|
| R1 | 揭示机制或差异 | 显示某制度怎样在地方被执行、变形、阻滞，或同一政策为何有不同落实方式 | “涉及制度，所以有价值” |
| R2 | 提供反例、失败、连续性或适应证据 | 能够修正一个已提出的解释；包括未实施、抵抗、恢复、延续、失败而非只有成功 | 自动把每个“未”字当反例；只保留支持既定衰亡/繁荣叙事的条目 |
| R3 | 为事先声明的序列、比较基线或过程提供节点 | 为同口径人口、水利、灾害、教育等序列提供观察点，或给过程定位 | 从孤立年度数字直接宣布出现历史转折 |
| R4 | 呈现被忽略的群体和少见经历 | 小群体的迁居、佃户负担、劳动者参与、妇女机会等能帮助回答具体问题 | 只有“人数少所以珍贵”；凭单书宣称史上唯一 |
| R5 | 有助于研究记载本身如何产生 | 版本异文、承袭、报告日期、叙述口径与选材变化，可解释“何以被记、何以不见” | 凭空宣称旧志与新志矛盾；把AI措辞差异当成原书差异 |

R3意味着：一条年度人口数字不一定进入主线，但可以成为人口专题的完整观察序列的一点。集合价值不要求每个成员都是“大事件”。LoGaRT的方法论文强调以整个材料集合回答问题，并反复从整体分布回到单条记录。[2]

## 四、四层实际去向

| 工作层 | 进入条件 | 默认展示 | 后续动作 |
|---|---|---|---|
| `core` 主线 | 有明确、足以支撑较大历史后果的记载，且与研究区域有关 | 主线年表 | 重点核读后果、时间与来源，允许撤回 |
| `topic` 专题 | 局部实质改变，或对启用研究问题有具体可说明的作用 | 专题和同期视图 | 比较、串联、与其他文献互证 |
| `clue` 待核线索 | 潜在重要，但后果、关联、日期/地点等关键解释仍不足 | 独立待核层，未定年不隐藏 | 带着具体缺口补查，不自动无限追索 |
| `archive` 底库 | 当前只有例行记事、宣传、孤立观察或无本地关联，且没有已说明的研究用途 | 主线隐藏，底库和全文检索可见 | 按来源/年代抽样反查，研究问题变化后重筛 |

这里的“archive”不是从数据库归档删除，也不是永不重用。四层都是同一工作区中的可切换视图。

### 简化决策次序

1. 原文能够支持什么？有来源、引文和页码吗？日期和地点不清楚时，保留“不清楚”。
2. 有没有具体的实际改变？有，则判断范围、时间性质和不可逆性，进主线或专题。
3. 没有显著改变，是否能具体回答某个研究问题？有，则进专题。
4. 只有潜在线索？进待核，明确要补什么。
5. 两条通道均不成立？留底库，不占主线。

不设置“每县每年最多十条”“淘汰80%”“分数超过70才纳入”等先验指标。筛选比例是结果，不是目标。

## 五、通常不直接进入主线的八类记载

例行会议、视察检查、开幕奠基剪彩、普通表彰、例行任免、孤立年度统计、空泛成就表述、没有实施证据的计划。

这些是需要追问后果的类型，**不是词语黑名单**。会议可能改变了土地征收权；任免可能是一次实际权力转移的节点；仪式也可能揭示统治、组织或记忆生产。只要具体材料支持，仍可按C2或R1—R5进入适当层次。

不要让“具有重大意义”“开创先河”“受到重视”“规模盛大”“著名人士”“首次”“重点工程”等修辞自动加分。相反，也不要因为来源带有官方或其他明确立场，就不经对读把其全部事实信息排除。

## 六、必须保住的反向案例

以下都是规则说明用的构造案例，不是闽南史实：

| 条目 | 处理 |
|---|---|
| “召开工作会议、听取汇报” | 没有后果与研究用途时留底库 |
| “会议后全县土地征收权实际改归某机构，沿行五年” | 不能因含“会议”剔除；有C1/C2主线候选 |
| “铁路已列入计划，但因资金/组织争议没有实施” | 不是铁路建成；实施差异研究可入专题 |
| “三十户被迫迁居，耕作安排随之中断” | 不因规模小消失；至少局部影响/群体研究候选 |
| “某年人口二万人” | 单点通常不入主线；启用同口径人口序列后进入专题观察点 |
| “某实践继续传授，经历组织改变后仍然延续” | 不因不符合衰亡预设而排除；可以修正解释 |
| “新志记某机构成立于1931年，旧志记1932年” | 同事件异文待对读，出版晚不自动胜出 |
| “甲县志未记水灾” | 不能直接当作甲县没有水灾，先看覆盖、体例与资料来源 |

灾害史研究说明，地方志中的记录与沉默还受编纂、抄录和报告过程影响。应研究这些过程，不能把有/无条目机械等同于事件有/无发生。[3]

## 七、研究者最终核读的五句话

对准备放入主线的事项，要求能写出：

“改变了谁的什么条件”；“改变是实际记载还是推断”；“范围、延续或严重性依据何在”；“为什么与闽南有关”；“不纳入会漏掉哪个具体过程或解释”。

第五句是帮助选材的省略检验，不是证明历史因果的反事实实验。

本标准不把所有文化对象都变成研究任务。默认研究配置围绕生计、组织、制度落实、迁移、实践再生产和历史叙述形成，不因为某物是民俗、名胜或知名人物就自动扩大研究范围。

## 八、标准如何落实在代码

`config/research_profile.json`保存研究问题、主线适用空间尺度和候选召回配置。`prompts/assess.md`要求模型提交具体影响/用途及逐字证据。`selection.validate_assessment()`核对结构与引文；`selection.decide()`决定机器工作层。

校验程序只能验证“引文确实在材料里”和“结构合法”，不能机械证明解释正确。这是原页抽样和人工研究判断仍然必要的原因。

`rules`模式是少量显式词形与否定保护组成的离线基线，只保证流程可运行、便于测试与初步排队；不是成熟的历史重要性模型。正式选材可用既有Agent或一个主模型，仍须用实际资料校准。

参考文献[1]—[3]见`07_联网研究依据.md`。

# 02｜施工与运行手册

所有命令从项目根目录执行。示例中的`work-real`是待创建的新工作区，`D:/gazetteers`等路径应换成实际资料位置；不要覆盖现有文件或把构造数据放进真实工作区。

## A. 先做全目录盘点，不要求你预先手工整理全书

```bash
python run.py scan "D:/gazetteers" --out catalog.draft.json
python run.py locate "D:/gazetteers/某县志.pdf" --out locate.hints.json
```

`scan`读取文件名与路径，不把它们当作已经核定的书名版本。`locate`检查可读取文字中的大事记、凡例等标题，给候选页；它不自动认定页段，不对无文字PDF反复OCR。

执行Agent核读目录与凡例，把`title / edition / county_group / chronology_pages / preface_pages / calendar_rule`填入书目清单。页段采用**文件实际页序，从1开始**，不等同于书内印刷页码。明确全文件就是大事记摘录时才设`whole_is_chronology=true`。

范围不明确时先登记来源，返回`needs_page_selection`；不擅自把整部志书当大事记。

版本不同使用不同`source_id`。同一ID的底本字节变化会被拒绝，避免把修订前后版本混在一起。原书没给出的信息留空或注明待核，不补猜测。

## B. 文字输入与原件

三种受支持路径：

- TXT/Markdown：UTF-8；可用换页符`\f`表示实际分页。
- PDF：读取现有文字层，保存原件与页号。无可靠文字的页标为`needs_reading`。
- 分页JSONL：每行`page_no / text / printed_page(可空) / status(可选)`，由已有识读工具提供。

复杂版式先对连续若干页检查阅读顺序。PyMuPDF的`sort=True`是简单排序，不是通用古籍版面理解。[6]

如果先用外部工具识读扫描PDF，保留原PDF并按本包`import-records`格式挂接原件；条目页号继续使用原PDF实际页序。分页文本、清洗结果不要覆盖原PDF。识读模型参数不是本项目的强制逐条审批字段；能保留来源说明就保留，首先确保底本能回看。

```bash
python run.py ingest --workspace work-real --manifest catalog.reviewed.json
```

或者已有结构化原条目：

```bash
python run.py import-records --workspace work-real --file records.jsonl
```

导入过程按来源/条目报告错误，其他成功部分保留。原条目定位符和原文不能被重复导入静默覆盖。更正识读本时以新来源/校订版本重新导入，保留与旧本的关系；事件解释性更正用`amend`，不是改原文。

## C. 日期继承与节点抽取

规则切分按照连续编年段继承显式年份/月日，支持跨页，不跨书，不越过未处理页段。正文中的“曾在某年”不更新编年上下文。复合条目默认不乱拆；模型抽取可拆成独立行动，所有节点仍连回完整原条目。

先以规则查看：

```bash
python run.py extract --workspace work-real --mode rules
```

正式语言抽取选择其一：使用文档04的既有Agent任务交换；或者配置实际模型服务后：

```bash
python run.py extract --workspace work-real --mode llm --replace-seeds
```

`--replace-seeds`只替换尚未人工核读、没有有效关系、且来自rules的节点。不会替换人工选择或已对齐内容。模型输出非法、引文不匹配或被截断时旧节点仍在。

要重复跑一份新的抽取实验，使用新的实验工作区或明确的版本管理，而不是删除原数据“让它重新学”。

## D. 选材初筛

```bash
python run.py screen --workspace work-real --mode rules --profile config/research_profile.json
```

正式语义判断可替换成`--mode llm`，或让已有Agent回答导出的`assess`任务后用`apply-assessments`导入。

```bash
python run.py screen --workspace work-real --mode llm --profile config/research_profile.json --resume
```

`--resume`在研究配置和证据输入未变时复用已完成筛选。模型调用缓存还区分模型、完整提示词和输入。人工选择不被重跑覆盖。

配置改变时重跑`screen`。例如启用人口观察序列，原来的孤立统计可以转入专题；这不是伪造事件，而是研究用途发生变化。默认配置没有预设“文化一定灭亡”或“发展必然进步”。

## E. 跨县对齐与第二轮选材

```bash
python run.py align --workspace work-real
python run.py serve --workspace work-real --open
```

所有工作层均参与候选召回，底库不被排除。候选来源包括精确相同文本、特征实体、相近时间下的稀有词片组合。特征工程/机构名称允许跨年匹配以发现日期异文。

“没有候选”不代表无关联；“相似”不代表同事件。现有实现不对全库做保证完全召回的两两推理。界面选择同事件、相关、不相同或暂不决定。必要时可人工补候选：

```bash
python run.py candidate --workspace work-real EVENT_A EVENT_B --reason "工程名称对应，但纪年不同，需并读"
```

同事件关系可撤销，保留各版本日期。开工、完成、奏报、施行、后果应保留不同阶段。过程关系可用命令维护：

```bash
python run.py link --workspace work-real EVENT_A EVENT_B part_of --reason "原书明确将其列为同一过程的两个节点"
python run.py unlink --workspace work-real RELATION_ID --reason "复核后并非同一事件"
```

`source_reports_cause`只是“来源报告了因果关系”；`hypothesis`是研究假设，均不是已证明因果。

完成人工同事件对齐后再运行`screen --resume`，新证据会触发相关条目重筛。没有新增证据的条目不反复消耗模型。原文承袭关系要另看来源说明，不能用“出现三本书”投票。

## F. 人工核读不是每条点批准

先看有重大后果的主线候选、冲突、年份/地点疑难、潜在线索，再对普通专题和底库分层抽样。

```bash
python run.py sample --workspace work-real --out work-real/outputs/review_sample.jsonl --per-tier 20
```

抽样覆盖工作层、来源和年代段；样本预留人工标签。不根据这份不等概率小样本直接宣称总体准确率。抽取召回率另用“连续原页上本应有的全部条目”建立分母，不能只检查系统已经找出的条目。

人工改层可在网页操作，也可用命令：

```bash
python run.py select --workspace work-real EVENT_ID topic --reason "局部生计改变有材料，但不足以列为区域主线"
python run.py select --workspace work-real EVENT_ID auto --reason "取消这次人工选材，恢复机器建议"
```

人工核定是研究判断，不等于对该来源全部事实作真实性担保。网页会分别显示机器/人工选材状态和来源事实限定。

## G. 导出、备份和使用

```bash
python run.py export --workspace work-real
python run.py status --workspace work-real
python run.py backup --workspace work-real --out backups/chronicle.sqlite3
```

导出目录默认`work-real/outputs/publication`，包含单文件HTML、主线/专题/待核/底库Markdown、年表CSV、跨县长表CSV、完整JSONL和来源清单。CSV是阅读输出；潜在公式文本有安全前缀。无损转存使用JSONL，不拿CSV覆盖原始材料。

`backup`通过SQLite一致性备份接口复制数据库；原文件、外部导入和必要配置应一并随工作区备份。不要仅复制运行中的sqlite文件而漏掉已提交WAL数据。[7]

旧系统接入使用CLI、JSONL和Markdown三个稳定出口。无需让autoresearch控制每一步，不需要重构用户法律工程。当前没有直接向Wiki、Drive或GitHub推送的连接器；产物由原有工作流接收。

## H. 一条命令贯通与排错

书目经过核对之后，可以连续运行：

```bash
python run.py run --workspace work-real --manifest catalog.reviewed.json --mode llm --profile config/research_profile.json
```

它顺序执行导入、抽取、初筛、候选和导出；不自动采用对齐，不对外发布。纯离线流程改为`--mode rules`。

| 情况 | 处理 |
|---|---|
| needs_page_selection | 补实际大事记页段，勿把整本默认吞入 |
| needs_reading | 原页留存，补可靠分页文字，不反复重跑相同无效识读 |
| 年号未换算 | 仍保留原纪年与未定年视图；带出处修订年级结果 |
| quote不是原文片段 | 让Agent改回逐字引文，不关闭校验 |
| 模型JSON被截断 | 缩小单元或调整服务允许的输出预算，不能当成功结果 |
| HTTP 401/参数不支持 | 核对现有服务配置；不猜新模型名/地址；可继续既有Agent文件交换 |
| 老缓存持续返回错误结果 | 核对提示词后设`LLM_DISABLE_CACHE=1`重试受影响任务；不清空原件/人工数据 |
| 网页保存无效 | 静态HTML只读；改用本机`serve`。不是发布站点，不接受外网写入 |
| 某条人工选择未随模型改变 | 正常保护；明确恢复auto才采用模型建议 |

用户实际资料规模、版式和服务器吞吐尚未测量。全量运行前，先拿真实小批次测每页识读、每条抽取/筛选用时、错误率和缓存命中，不给空泛费用或吞吐承诺。

## 3. 九张实际数据库表

`source → page → record`是材料链；`event ← evidence → record`是解释与引文关系；`place`提供地名候选；`candidate`提供待对读配对；`relation`保存人工关系；`decision`保留简洁修改记录。

实际表名：`sources/pages/records/events/evidence/places/candidates/relations/decisions`。数据库模式在`db.py`，不再另外生成可能漂移的“伪SQL规范”。

一个record可支持多个event。一个same_event组可以含多个来源节点，系统不抹平它们的日期和用词。来源数不是独立证据数；同一事件在多个县分组显示只计一个组。

模式版本2面向本包新工作区。没有实现任意旧数据库自动迁移；若已有外部数据库，应写一次性导入器、保存原库，再用契约测试验收。

## 4. 输入输出契约

### 书目清单

`schema_version=2`，顶层`sources`数组；每项含`source_id/path/title/edition/county_group/calendar_rule`和实际页段。范例见`examples/manifest.example.json`与`manifest.blank.json`。

`calendar_rule`取`unknown/gregorian/lunar/julian`等明确书目口径，其中只有`gregorian`允许程序将原月日用于公历校验；其他值保留原历法显示，不进行伪换算。

### 原条目导入

每行`source`＋`record`，或已登记的`source_id`＋`record`。record至少有`locator/raw_text`，通常提供实际页序、date_raw、context。原始文本不应夹带研究者猜测；研究解释写入后续层。

### 模型抽取

每条返回`events`非空数组，字段和取值见`prompts/extract.md`。每节点`quote`必须是本原条目的连续逐字片段；日期必须来自该引文或显式继承上下文。无法拆分时返回一个narrative节点，不能空数组悄悄删除。

### 选材判断

外部文件每行`event_id/assessment`。assessment包含`scope_relevance/impacts/research/routine/unknowns`。引用必须指向当前提供的材料。研究用途必须绑定启用的question_id。无“请直接打一个80分”的接口。

### 对齐与输出

自动候选与自动建议不是关系采用。只有人工`link`后才进入same_event组。最终出口使用稳定ID、原文、来源、异文和选择状态，不能只输出一段失去出处的摘要。

## 5. 真正开工的批次

**第一批：盘点全部来源，处理少量真实样本。** 避免把“样本”误成挑最好识读的三本；优先含年代重叠、版本不同、版式有差异的约3—6部志书。若实际只有一种版式或少量书，不为凑数增加虚假类别。

**第二批：建立约200—300条人工核读样本。** 从连续原页抽出，而不是从模型已挑出的漂亮条目抽出。刻意包含会议/实施、计划/失败、短小古代记载、少数群体、孤立数据/序列、同名异地、跨年异文。样本量是工作建议，不是统计充分性的声明。少量样本仍可先开工，但不宣称总体正确率。

**第三批：校准两条判断链。** 一条测原页到条目的遗漏、合并、切错；另一条测事件到选材的误纳和误降。不能让负责抽取的同一批模型答案充当独立金标准。用户裁决写成具体例子，更新研究配置/提示词，必要时修改轻量规则。

**第四批：全量导入和初筛，所有层参与候选。** 同时交付可读总表、来源覆盖和问题队列；不以全部年号换算/全部冲突解决为上线门槛。再进行人工对齐与有新增依据的定向重筛。

**第五批：连接既有研究工作流。** 稳定接收JSONL与Markdown；不把它当成有权自行撰写和发布通史的系统。

## 6. 真实验收指标应分开报告

| 项目 | 正确分母与核查方式 |
|---|---|
| 原条目召回 | 连续样本页上人工枚举的全部条目，而非已抽取条目 |
| 日期/地名正确性 | 已独立核读的日期/地点字段；未解析要另计，不能当成功 |
| 主线误纳 | 被选为主线的样本里，无后果/无依据的比例及具体原因 |
| 值得研究材料误降底库 | 人工认为主线/专题的样本中，被机器藏进底库的情况 |
| 对齐误合并 | 人工确认的关系，按事件和阶段对照；不以相似度代替 |
| 对齐候选遗漏 | 小规模人工配对样本中的已知相关/同一事件，是否被召回 |
| 原件可回看 | 从事件经record/source到文件页的抽查，PDF和印刷页分开 |
| 工作区稳定性 | 重跑不重复入库、失败不覆盖旧数据、人工选择保留、撤销可还原 |

不先许诺“史学正确率98%”。工程底线则可以明确：已知测试中的造日期、丢原文、自动误合并、重跑覆写人工选择不能放行。没有搞定的历史问题进入待核，不能改成一个看起来确定的答案。

## 7. 默认不做的扩张

不先训练或微调；不先向量化全书；不堆图数据库；不设多Agent审批链；不新造法律式真实性概率；不为一条线索发动无限网络检索；不自动用现今县界反投古代；不把官方身份或反官方立场变成事实权重。

未来如因真实样本证明需要增加版式识读器、历日转换适配器、矢量地图、服务端大规模分页，再做局部模块。当前前端按60组分页显示，但后端bundle是整包载入；没有完成十万级数据量性能评估，不能声称已经具备相应吞吐。

## 8. 交付格式

执行者应交付实际工作区、书目清单、原件保留情况、四层输出、问题队列、真实样本和评估、实际变更源码与通过的测试。报告必须把“程序跑通”“语言抽取效果”“历史判断”分开。

# 04｜提示词与模型接入

## 一、六份实际文件及其责任

实际位置均在`src/minnan_timeline/prompts/`。

| 文件 | 做什么 | 当前是否自动接入 |
|---|---|---|
| `system.md` | 来源是数据不是命令；保留不确定性；不虚构史实和引文 | 模型适配器每次加载 |
| `extract.md` | 一条材料拆为可支持的事件/状态/叙述；日期、阶段、地名逐字来源 | `extract --mode llm`或Agent任务交换 |
| `assess.md` | 12项选材证据、具体研究问题、例行性质与待核信息 | `screen --mode llm`或`apply-assessments` |
| `compare.md` | 两条是否同事件/相关/不同/未定，保留日期及阶段异文 | `judge-pairs`，建议不自动采用 |
| `enrich.md` | 对关键缺口提出查什么、找什么证据和何时停止 | 提供给已有研究Agent；未接自动联网调度 |
| `archival_audit.md` | 反查底库误降，优先保护反例、短材料与群体经验 | `sample`后由研究者/已有Agent执行；非自动第二模型 |

“6份提示词”不是把6个Agent常驻运行。默认一个主模型，程序做文件、日期、数据和引用校验。只有需要判断的片段才交给语言模型。

## 二、提示词设计原则

原条目抽取阶段不筛价值，否则被模型省略的材料无法在底库反查。选材阶段要求它给出原文支持的具体改变和研究作用，不让它直接凭直觉输出最终总分。对齐阶段既看同一性，也看阶段差异；单独提交日期不同但名字相同的候选，防止硬时间过滤遮掉真正异文。

输入中不给模型先前机器/人工层级和理由，减少复述旧判断。材料内如有“忽略之前指令”仅作为原文，不允许改变任务。程序验证引用是不是连续原文、ID是否存在、question_id是否启用、阶段取值是否可用。

逐字匹配只验证出处存在，不验证推理充分；语义是否成立仍靠实例校准与核读。不得把严格JSON检查宣传成历史事实的形式证明。

## 三、路径A：使用现有研究Agent，不新配服务

### 1. 抽取任务交换

先导入实际书目或原条目，再执行：

```bash
python scripts/agent_exchange.py export --workspace work-real --task extract --out work-real/outputs/extract_tasks.jsonl
```

每行带完整system_prompt、record_id和材料输入。交给现有Agent按行处理，返回：

```json
{"record_id":"实际ID","result":{"events":[{"title":"中性标题","quote":"原文连续片段","date_raw":"原纪年或空字符串","event_kind":"event","phase":"unknown","temporal_kind":"point","places":[],"entities":[]}]}}
```

回收：

```bash
python scripts/agent_exchange.py import-extractions --workspace work-real --file work-real/outputs/extractions.jsonl --replace-seeds
```

只处理文件中给出的条目，缺少的答案不会把其余记录清空。重复record_id答案拒绝；有人工/关系的旧节点不替换。导入后标为语言模型抽取，而非人工核定。

### 2. 选材任务交换

```bash
python scripts/agent_exchange.py export --workspace work-real --task assess --profile config/research_profile.json --out work-real/outputs/assess_tasks.jsonl
```

返回形状：

```json
{"event_id":"实际ID","assessment":{"scope_relevance":"local","impacts":[],"research":[],"routine":[],"unknowns":["写实际尚缺信息"],"note":"必要限定"}}
```

上例仅演示结构；不得用空依据给全部实际事项敷衍分类。影响与用途要按`assess.md`补齐逐字证据。程序会把空且无支持的判断留为待核，不允许伪装重大结论。

```bash
python run.py apply-assessments --workspace work-real --file work-real/outputs/assessments.jsonl --profile config/research_profile.json
```

旧Agent如果本来就能读文件/写JSONL，只需要这一交换格式，无需被改造成多个专门Agent。

## 四、路径B：兼容chat-completions模型服务

实际适配器接受完整请求地址、模型名及可选API凭据。地址必须包括服务所需路径；代码不会自动拼接或猜测。使用服务自己的官方文档核对，不能把示例占位符当真实端点。[8]

PowerShell设置示意（值必须替换成实际配置）：

```powershell
$env:LLM_ENDPOINT="YOUR_COMPLETE_CHAT_COMPLETIONS_ENDPOINT"
$env:LLM_MODEL="YOUR_AVAILABLE_MODEL_NAME"
$env:LLM_API_KEY="YOUR_EXISTING_KEY_IF_REQUIRED"
python run.py extract --workspace work-real --mode llm
python run.py screen --workspace work-real --mode llm
```

macOS/Linux使用`export LLM_ENDPOINT=...`等环境变量命令。`.env.example`是配置参考，程序不会自动读取`.env`，不引入dotenv依赖。已有运行环境能设置变量时直接复用。

有些服务不支持`response_format`时设置`LLM_JSON_MODE=0`；仍然必须返回可解析的JSON。`LLM_MAX_TOKENS`和`LLM_TEMPERATURE`为可选项，不默认向所有模型强塞同一参数。默认非流式，`message.content`必须是字符串。

服务HTTP 408/429/部分5xx会有限重试；401等配置错误直接报告。被截断、非JSON或缺关键结构的回答不写成成功结果。调用缓存不存API密钥，缓存命中不意味着历史内容已被核定。

## 五、局部补查与停止条件

`enrich.md`不是一个已经连接网上所有数据库的程序。研究者/已有Agent仅对有价值且具体的缺口执行，例如“究竟是批准年还是实施年”“竣工后是否通行”“新志是否承袭旧志”。优先补同书相关卷章、旧/续志、实际档案和可核出处，再考虑网络索引。

每个任务写明：缺什么、哪种材料可以解决、找到什么就足够、哪些否定发现会降低判断。无收获要报告“尚未取得”，不以换模型生成更笃定的语言结案。

## 六、如何迭代提示词

先保存一批用户已经核读的反例及理由，再修改对应提示词或研究配置；重跑这批样本观察误纳和误降。不得根据本包构造案例的高一致性宣称真实语料有效。不要把测试期望标签传入待测模型输入。

模型要做的是提取和提出解释；研究问题、价值判断、最终采用由研究者掌握。提示词须允许与既有宏观解释不一致的材料进入专题，而非帮助模型证明预先写好的结论。

# 05｜时间、地名与证据规则

## 1. 年表位置不能比材料更精确

实际实现保留`raw/label/start_year/end_year/month/day/precision/kind/calendar/status/notes`。日期未定则为空，不自动填1月1日。时间标签是资料所支持的精度，不是供程序排序方便而伪造的发生日。

民国年到公元年可作年级换算，但不能由“民国”或阿拉伯数字推断月日使用公历。年号识别词表只是切分辅助，**不是年号年代数据库**；不支持的年号不继承上一个公元年，不由模型常识猜年。后续可以通过有出处的`amend`修订。

中研院历日工具对缺日/缺月日输入可能返回月首/年首，这些默认输出不能代替事件日期。[4] 当前包没有内置该网站的自动请求接口，也没有承诺完整转换干支、闰月、朝代与古历日。

## 2. 不同时间语义

“1931—1933年持续施工”是duration；“约1931—1933年间成立”是uncertain；“某年秋”保持原季节。它们不互相替换。月份/日期只有在明确公历时校验精确顺序；其他历法保留原月日，年表主要作年级对齐。

公元前用负历史年份存储，不设置公元0年；前1年的翌年为公元1年。浏览端不使用JavaScript Date推算古代日期，避免其年份/时区默认行为污染历史时间。

同年但月日不详的多件事只能并列，显示排序不能作先后结论。跨年过程不扩写成每年重新发生一次。异文组排序采用某个资料年标签只是阅读方式，不等于裁定唯一日期。

## 3. 事件时间与记载时间

区分proposal/decision/start/implementation/completion/report/aftermath等阶段。奏报水灾的一天，不一定就是水灾发生日；机构批准和实际运行也可能是不同事件。只有明确关系时连为过程，不自动合并。[3]

“首次见于本次材料”不同于实际起源。材料保存下限不是现象产生上限；没有见到更早记载不能自动证明此前不存在。

## 4. 来源地域与发生地域分开

来源出自某县志，不等于事件发生于该县。县志可能记全省命令、邻县变化、本地人在域外的经历。`county_group`只是书目浏览分组；事件places仅放原文可见的地名，不能从标题补入。

地名表按`place_id/name/aliases/valid_from/valid_to/modern_names/basis`导入。有效范围重叠且同名多地时保留多个候选。今地名用于检索辅助，不能覆盖古地名和历史隶属。

CHGIS提供随时间变化的名称、行政关系与地点资料，但县级点位不等于完整县界。[5] 当前只实现轻量本地名称表，不附带其完整数据、不建立地图，不声称已下载或联通CHGIS。

## 5. 原件、条目、事件解释

保留完整原文件；原条目另存逐字文本和定位；事件是可修订解释；原文承袭关系尽可能登记在source metadata中。不能让模型摘要覆盖原文，不能把两个版本改成一份“最通顺”的统一记述。

PDF实际页序用于文件定位，印刷页码是另一字段。外部导入没有挂接底本时界面明确显示“尚未挂接”，不能伪造原件链接。

多书同文只是多处记载。明确引旧志时登记承袭；仅文字近似则是疑似承袭，不能假定三份独立证据。资料出处不自动赋予真实概率，人工选材也不自动认证全部史实。[3]

## 6. 空白和数量

区分：没有对应书、没有处理该页段、缺页/无可靠文字、未定年、已处理但没有检出、筛选后没有显示。它们都不是“历史没有发生”。

来源覆盖表只反映本批材料和处理状态，不证明各年代资料等量。一个年代的记录变多，可能与编纂、版本、体例和保存有关；需结合实际材料集合审查，不能直接解释成历史更活跃。[2]

同事件组在甲乙两县显示仍只计一个组；统计原文条数和统计事件组是不同分母。还没人工对齐前，事件组可能暂时重复，不能把系统暂存计数当作事件发生总量。

# 07｜联网研究依据

检索核读日期：2026-09-11。以下是设计所依据的原始论文、研究项目和官方文档，不是对用户未提供志书内容的引用。设计规则由本项目制定，不能宣称论文已经验证这套分类器。

## [1] 历史重要性不只有“规模大”

Historical Thinking Project. *Historical Significance*.
https://historicalthinking.ca/historical-significance

用途：同时考虑广泛/持久改变与能够揭示大问题的个体经历；“在史书里”或“我感兴趣”都不足以直接证明历史重要性。

限度：历史教育/方法项目，不是地方志自动分类器的量化验证。C1—C7、R1—R5是本项目细化规则。

## [2] 集合查询与单条细读往返

Chen, Shih-Pei; Yeh, Calvin; Wang, Sean; Che, Qun. *Treating a genre as a database: a digital research methodology for studying Chinese local gazetteers*. International Journal of Digital Humanities 4, 171–193 (2023); online 2022-10-06. DOI: 10.1007/s42803-022-00048-5.
https://link.springer.com/article/10.1007/s42803-022-00048-5

用途：将地方志集合按研究问题组织，结构化提取、整体分布与原记录往返、注意粒度和来源集合的时空分布。

限度：论文对大型地方志集合的论证不能直接证明本用户资料集合代表全部闽南历史；本文中的工具规模和当年统计不作为当前本包能力或数据量。

## [3] 记载数量和日期受报告、编纂与抄录影响

Schäfer, Dagmar; Chen, Shih-Pei; Che, Qun. *What is Local Knowledge? Digital Humanities and Yuan Dynasty Disasters in Imperial China's Local Gazetteers*. Journal of Chinese History (2020). DOI: 10.1017/jch.2020.31.
https://www.cambridge.org/core/journals/journal-of-chinese-history/article/what-is-local-knowledge-digital-humanities-and-yuan-dynasty-disasters-in-imperial-chinas-local-gazetteers/1B81A9D09D16DBCA91D0732C8804506A

用途：区分历史发生与记录形成，注意抄录、报告机制、地域差异和材料沉默；不能把同文多见视为多份独立证据。

限度：专门历史案例提供方法提醒，不证明每一本现代县志都有同样偏差，更不支持将全部地方志一概作废。

## [4] 历日换算默认值的风险

中央研究院：两千年中西历转换及网页使用说明。
https://sinocal.sinica.edu.tw/

用途：缺日或缺月日时可能返回首日；程序不能把这些默认值当作事件实际日期。保留原纪年、精度与转换依据。

限度：核查了网页及说明，没有确认稳定开放API。本包不猜测API，也不声称自动完成全部古历转换。

## [5] 历史地名和行政关系具有时效

China Historical GIS (CHGIS), Database Design / Introduction.
https://chgis.fas.harvard.edu/pages/database/

用途：历史地点名称、治所、边界和隶属变化须按时间处理；点位不能直接充当完整县界。

限度：本包只实现可导入的轻量时段名称表，不分发CHGIS全量数据，不将当前行政区划当作古代归属。

## [6] PDF文字顺序不是自然阅读顺序

PyMuPDF documentation, *Text* recipes.
https://pymupdf.readthedocs.io/en/latest/recipes-text.html

用途：优先读取既有文字层；阅读顺序需检查，简单排序不等于复杂版面理解。

限度：官方软件文档不能保证某部竖排古籍的提取质量。本次只实测构造文字PDF适配。

## [7] 本地数据库与一致性备份

Python documentation, *sqlite3 — DB-API 2.0 interface for SQLite databases*.
https://docs.python.org/3/library/sqlite3.html

用途：标准库数据库接口与backup方法，避免另建服务器、误复制活动数据库。

限度：本包尚未进行大规模性能评估；使用SQLite不等于已经获得任何数据规模下的性能保证。

## [8] 模型协议参考，不绑定供应商

DeepSeek API documentation, *Create Chat Completion*.

# 08｜施工Agent任务书：在现有可运行包上接入实际闽南志书

## 目标

把用户已有各县市地方志的大事记整理成原件可回看的跨县研究时间线。原始条目全留，按C1—C7、R1—R5分主线/专题/待核/底库，不照搬编纂者“大事”标签，不把主题热度和行政级别当历史重要性。

## 立即执行，不先另写一份泛化规划

1. 读`README.md`和`AGENTS.md`，实际运行测试、演示和本地网页。记录环境与未通过项，不把模拟模型测试称为真实模型联通。
2. 检查被授权的实际资料目录，扫描书目；读取目录/凡例，核定大事记页段和日期口径。用户资料路径未给出时只提出这一个真正缺项，继续完成不依赖路径的安装/演示验证，不猜目录、文件或页码。
3. 依据实际资料挑年代重叠、版式/版本有差异的小批次，保存底本，先抽取到可读总表。无可靠文字的页列出，复用已有文档识读工具，勿反复昂贵OCR。
4. 复用现有Agent执行`agent_exchange`任务，或使用现成模型环境的兼容服务。默认一模型，不新增多个常驻Agent，不要求用户购买新订阅。
5. 依12项标准做初筛；抽取时不删资料；底库仍参加对齐。程序/模型错误按局部任务报告，不能让已成功部分停摆。
6. 交付实际样本原页对照与初筛理由，请研究者核读关键差异；建立真实标签及反例，更新配置/提示词后重测。尽量从连续页抽样以发现漏条，不能只展示成功例子。
7. 全量处理，交付中文年表、跨县同期表、同事件异文、覆盖与待核表；人工对齐后仅重筛新增证据相关的记录。导出Markdown/JSONL交给既有研究流，不自动发布。

## 源码改动顺序

先调整`config/research_profile.json`，再调整对应`prompts/`；真实版式切分不足才改`ingest.py`；已经证实需要的历史历日/地名功能才写局部适配器。修改前增补真实失误的最小脱敏测试，修改后全量回归。不许以“更通用”为由推倒SQLite与现有CLI另建框架。

保留所有人工选择、原件、原条目和版本。换数据库结构必须先备份，明确迁移，不能仅改模式版本号。不要把模型认为错误的原文改成其常识中的“正确史实”。

## 每批实际交付

- 有来源位置和实际处理状态的材料清单；底本缺失/识读不足的明确列表。
- 可以现场启动的真实工作区和四层中文产物。
- 能从事件回到原文原页的对照，带异文与待核问题。
- 真样本的漏条、日期、误纳、误降和对齐错误说明；不混成总分。
- 实际修改过的代码/提示词/配置、通过测试及仍有缺口。

无需先“把所有历史研究完成”。但没有读到的文件、没有调用的模型、没有测试的功能，都不得报告为已完成。

## 完成标准

研究者能够选一个时段并排读各县，看到主线/专题差别，点回原页，理解为什么入选或暂存，处理同事件日期异文并撤销错误归并；全量原始条目可检索，重跑不会覆盖人工选材。做到这些后再根据真实研究需求增量改进，而不是先建宏大的历史智能体平台。
